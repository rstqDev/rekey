How it decides

It re-types the word

Every layout is described by physical key position, so Rekey can ask: if these same keys had been pressed on Russian, what would they have produced?

It scores both readings

Both spellings are scored against language models built from subtitle corpora — real speech, so they know норм, чувак, gonna and lol, not just dictionary words.

It usually does nothing

Passwords, terminals, acronyms, file paths, anything with a digit, and any word that is already real — all refused outright. Doing nothing is the safe answer and Rekey prefers it.

The numbers, including the bad ones

Why that last row is bad, and why it stays

Spanish and US QWERTY produce identical letters for a–z. Only ñ and the accent keys differ. German swaps y and z; French moves a handful of keys. For these, "typed on the wrong layout" barely exists as a failure mode — the letters come out the same either way, so there is almost nothing to detect.

Rekey ships them marked limited and holds them to a higher bar so they cannot churn ordinary English. What Spanish and German writers actually want is accent restoration — cancion → canción — which is a different feature and is not built yet.

Privacy

Everything runs locally

No telemetry, no analytics, no account, no network calls. The language models ship inside the app. With the optional assist off, Rekey never opens a socket.

The one exception, off by default

You can switch on Ask Claude about ambiguous words and supply your own API key. Then single ambiguous words — never whole sentences, never anything from a password field — go to Anthropic's API, and the answer is cached locally so each word is sent at most once.

Rekey needs Accessibility permission on macOS to see the keyboard. That is a lot of trust to ask for, which is why every line of it is readable.
